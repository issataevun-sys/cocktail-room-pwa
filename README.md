# COCKTAIL ROOM — единое PWA

**Один рабочий адрес:** https://issataevun-sys.github.io/cocktail-room-pwa/work.html

Версия: **v1.5, единое приложение без входа по пароль-фразе**.

## Что есть
- Схема зала, текущая смена, кальяны, VIP, мойка, брони, гости, списки, прошлые смены и система — на одной странице.
- Один зашифрованный workspace смен между подтверждёнными устройствами; iPad может сохранять изменения офлайн.
- При возвращении интернета неподтверждённые изменения отправляются автоматически. Конфликтующие правки одной записи сохраняются для сверки, не затираются.
- Локальная копия защищена **неизвлекаемым WebCrypto-ключом устройства** в IndexedDB; никакого ввода пароль-фразы в приложении нет.
- При первом подключении владелец регистрирует устройство средствами серверного реестра. Секрет устройства и ключ комнаты сохраняются **зашифрованно локально**, не публикуются в GitHub.
- Предыдущие локальные зашифрованные копии никогда не удаляются и не переписываются при отсутствии подходящего старого ключа.

## Реальные гости и история
- Сохранённая база **COCKTAIL ROOM — DATABASE** остаётся исходным источником гостей (лист `Guests`) и прошлых смен (листы `HistoricalShifts`, `HistoricalHookahs`, `HistoricalWashing`).
- Подтверждённые устройства загружают реальных гостей, индекс архива и сведения прошлых смен **по подписанному HMAC** read-only API. Архив кэшируется зашифрованно для повторного просмотра офлайн.
- Карточка гостя показывает историю старых посещений, если `guest_id` уже сопоставлен с историческими кальянами. Несопоставленные гости сохраняются в архиве для будущего ручного сопоставления.
- Новые и изменённые через PWA карточки синхронизируются в зашифрованном workspace устройств; **их обратная запись в нормализованный лист `Guests` ещё не реализована**. Исходные Google-таблицы не повреждаются.
- Исторические смены остаются только для чтения. Новые закрытые PWA смены показываются рядом без повторного импорта.
- История по дате или гостю доступна офлайн после первого открытия соответствующей карточки; при первом просмотре нужна связь.

## Зависимость от сервера (важно)
Новые маршруты архива определены в приватном репозитории `cocktail-room` (server-side `backend/PwaRelay.gs`, `backend/PastShifts.gs`, `backend/HistoricalImport.gs`). **После merge их нужно отдельно перенести в действующий Apps Script и опубликовать новую версию развёртывания /exec.** Одного изменения GitHub Pages недостаточно. До серверного обновления основная синхронизация комнаты продолжает работать, а запросы архива сообщают о недоступности вместо подмены реальных данных тестовыми.

Нельзя выполнять `clasp push --force`, пока не проверено, что файлы удалённого Apps Script и GitHub совпадают: это может удалить отсутствующие в GitHub файлы.

## Ограничения
Роли сотрудников и их PIN, автоматическая запись нормализованных заказов, iiko, автономное фоновое обновление iOS и полная автоматическая система резервирования — будущие этапы. Локальное удаление PWA при наличии неотправленных изменений опасно.
