# COCKTAIL ROOM — MANAGEMENT

**Единое приложение владельца и администратора.** Рабочая версия: **v1.4** (19.10.2026).

## Основные адреса
- Приложение: https://issataevun-sys.github.io/cocktail-room-pwa/work.html
- Корневая страница автоматически переводит в MANAGEMENT.
- Статическое приложение собирается только из `work.html`, модулей шифрования и синхронизации, `manifest.webmanifest`, `index.html`, `icon.svg`, `sw.js`.

## Проверено на реальных устройствах (19.10.2026)
- iPhone ↔ Windows: передача смены и кальяна в обе стороны.
- iPhone офлайн, Windows онлайн: независимые записи сохраняются и автоматически объединяются после восстановления связи.
- Закрытие смены офлайн с последующим появлением закрытой смены на двух устройствах.
- Google Sheets: зашифрованный снимок и подтверждения операций, серверная ревизия **11**.
- Резервная копия Google Sheets до теста и после успешного теста создана отдельно и доступна владельцу.

## Безопасность и текущие ограничения
- На разных устройствах отдельные `deviceId/deviceSecret`, общий `roomEncryptionKey`. Секреты **не размещаются** в репозитории.
- Изменения разных записей объединяются; параллельная правка одной записи блокируется до ручного разрешения. Данные не перезаписываются молча.
- Синхронизация при **закрытой** PWA на iOS не гарантирована; при возвращении приложения в активное состояние обновления проверяются автоматически.
- Исторические смены и реальные заказы Google Sheets/iiko пока не сведены в нормализованные рабочие листы; текущая синхронизация сохраняет зашифрованный снимок комнаты.
- STAFF, роли работников по PIN, история чеков iiko и автоматическая ротация резервных копий пока не готовы. Не выдавать сотрудникам ключ владельца.
- Никогда не удалять приложение, данные браузера или старые листы без подтверждённой резервной копии и проверки восстановления.

## Разработка
Только `main` публикуется на GitHub Pages. Новые функции делаются в отдельной ветке с автоматическими тестами в `tests/` и объединяются после проверки. Тестовые HTML-страницы и старый демонстрационный UI не включаются в публикацию.

Результаты финального сквозного теста: `FINAL_TWO_DEVICE_TEST_2026-10-19.md`.

## Предстоящая консолидация
1. В MANAGEMENT добавить подтверждаемое удаление выбранных тестовых записей с журналом действий и резервным копированием.
2. Подключить рабочие таблицы гостей/заказов, сохранив зашифрованную очередь.
3. Доработать права владельца/администратора и историю синхронизации.
4. Добавить автоматические резервные копии и проверку восстановления.
5. После стабилизации MANAGEMENT выделить отдельный STAFF без передачи owner-ключа.

## v1.4 — доверенные устройства владельца
- В «Система» владелец может один раз включить «Доверять этому устройству» на личном iPhone или Windows. При следующих запусках зашифрованная смена открывается автоматически, в том числе офлайн.
- Сохраняется **не фраза** и не извлекаемые байты ключа, а non-extractable WebCrypto CryptoKey в защищённом IndexedDB браузера. Владелец может отключить автовход отдельно на каждом устройстве. При ошибке ключа сохраняется ручной вход с прежней фразой; ни один снимок автоматически не стирается.
- Доверять **только личным** owner-устройствам. На общем iPad сотрудников не включать: кто разблокирует сам планшет, сможет войти в приложение владельца. Device enrollment остаётся необходимым, логин STAFF с персональным PIN будет отдельным.
- В «Система → Очистить тестовые записи» остаётся ручное выборочное удаление, резервная локальная зашифрованная копия и серверная CAS-проверка версии.
- Реальное Google Sheets-хранилище работает как зашифрованный снимок; нормализованные листы заказов, iiko, роли STAFF и автоматическое серверное резервирование **ещё не реализованы**. Нельзя считать v1.4 полностью готовой для всех бизнес-процессов.
- Автовход протестирован автоматически в Node.js; фактическую работу браузерного IndexedDB на iPhone нужно подтвердить один раз пользователю.
