# COCKTAIL ROOM — рабочая синхронизация без Google Cloud

**Статус: разработка на отдельной ветке `feature/offline-online-sync`. В рабочее приложение ещё НЕ внедрено.**

## Что подтверждено на реальном iPhone (18 октября 2026)
- GET через Google Apps Script JSONP работает.
- POST без CORS отправляется; успешную запись нужно подтверждать отдельным подписанным запросом ACK.
- Подписанный тестовый запрос и AES-GCM-шифрование на клиенте работают.
- Повторная отправка тестовой операции не создаёт вторую запись.
- Тестовая версия v2 сохраняет зашифрованный payload в Script Properties.

## Начат переход к рабочему приложению
- `cocktail-room/backend/PwaRelay.gs`: зашифрованная смена в отдельных листах Google Sheets, номер ревизии, подпись владельческого устройства, подтверждения и дедупликация. Сервер не расшифровывает данные. **Не пишет в HookahOrders и не заменяет действующую CR Sync.**
- `cocktail-room/backend/Code.gs`: на этой ветке изолированный обработчик `?pwa=1`; обычный HTML остается под существующей проверкой владельца.
- `cocktail-room-pwa/pwa-relay-transport.js`: клиентское AES-GCM, HMAC, GET/POST, ACK, стабильные идентификаторы операций для повторных попыток.
- Тест логики серверного протокола в окружении с имитацией Apps Script: создание записи, подтверждение, чтение, блокирование дубликата, конфликт версий, отказ без подписи — пройден. **Это не тест реального развёртывания.**

## Оставшиеся обязательные работы
1. Интегрировать транспорт в исходную страницу `work.html` без потери существующего офлайн-снимка на iPhone.
2. Безопасно сохранять настройки авторизованного устройства и очередь операций в зашифрованной IndexedDB; не в открытом localStorage.
3. На каждое изменение — сначала локальный коммит, затем отправка при соединении; авто-повтор после возврата приложения на передний план.
4. Поддержать жизненный цикл смены, открытие/закрытие, восстановление и действия с гостями/справочниками.
5. Реализовать проверенные права сотрудников и роли для доступа к данным. На текущем этапе API разрешает только предварительно зарегистрированные устройства владельца.
6. Сохранить конфликтующие изменения без перезаписи, показывать администратору/владельцу варианты слияния.
7. Перевести валидированные данные в существующие листы Google Sheets (`LiveState`, `HookahOrders`, etc) по правилам рабочей схемы. Сейчас API хранит **только непрозрачный зашифрованный снимок**.
8. Провести проверку безопасности, аудит и резервное копирование до включения реальных данных.
9. Не публиковать устройство, пароль, room encryption key или PIN в GitHub. Новая открытая Web App /exec будет нужна только при готовности защищённого кода.

**Внимание:** Это не повод сейчас заменять текущий рабочий Code.gs или PWA. Новые эксперименты с отдельными диагностическими страницами прекращены. Следующая практическая проверка должна проходить непосредственно в интерфейсе COCKTAIL ROOM, когда связка будет готова.
